# SHARK OSINT

Рабочий Telegram MVP для проверки **собственных аккаунтов и публичной информации с разрешения владельца**. Реальные Sherlock 0.16.2 и Maigret 0.6.6 работают в изолированных дочерних процессах. Независимый модуль SpiderFoot импортирует разрешённые CSV-экспорты; автоматические сканы SpiderFoot отключены по причинам ниже.

В коде приложения нет демонстрационных результатов. Подменённые ответы используются только в `tests/`. Платные API, прокси для обхода блокировок, утечки баз и поиск закрытых данных не используются.

## Быстрый запуск на Windows 11 x64

1. Установите Python 3.11+ x64 с python.org; рекомендуется Python 3.12. Git нужен только для необязательной установки SpiderFoot.
2. Распакуйте проект в обычный локальный каталог, например `C:\Shark\shark-osint`.
3. Запустите `start.bat`. При первом запуске он создаст `.venv`, установит зависимости, скопирует `.env.example` в `.env` и откроет его в Блокноте.
4. Заполните в **локальном** `.env`:

   ```dotenv
   BOT_TOKEN=ваш_токен_от_BotFather
   ADMIN_TELEGRAM_ID=ваш_числовой_Telegram_ID
   ```

   ID — число вашего личного Telegram-аккаунта, не имя пользователя, ID бота или группы. Токен получите у [@BotFather](https://t.me/BotFather). Не отправляйте токен в чат и не добавляйте `.env` в Git.
5. Сохраните `.env` и повторно запустите `start.bat`.
6. Откройте личный чат с ботом и отправьте `/start`.

Бот обслуживает только `ADMIN_TELEGRAM_ID` и только личный чат. Для реального запуска необходим интернет и доступ к Telegram Bot API. Окно терминала должно оставаться открытым. Остановка — `Ctrl+C`.

Ручная установка в PowerShell:

```powershell
cd C:\Shark\shark-osint
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
.\.venv\Scripts\python.exe main.py --check
.\.venv\Scripts\python.exe main.py
```

Если используется Python 3.11, замените `-3.12` на `-3.11`. Активация окружения и изменение ExecutionPolicy не нужны. При обновлении исходников повторите `pip install -r requirements.txt`; `start.bat` автоматически устанавливает зависимости только при первом запуске.

## Linux / текущее рабочее окружение

```bash
cd /workspace/shark-osint
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Заполните .env в локальном редакторе.

```

В среде разработки `.venv` уже создано и зависимости установлены. Linux-окружение `.venv` нельзя переносить на Windows: `start.bat` создаёт новое. Архив исходников не включает `.venv`, `.tools`, `.env` или пользовательские данные.

## Возможности

- Inline-меню: поиск по нику, история, мои отчёты, настройки, о системе.
- Один ник за запрос; проверка формата, запрет списков, телефонов, адресов и командной инъекции.
- Асинхронная ограниченная очередь: один активный поиск на пользователя, один поиск в работе, пауза между запросами.
- Параллельная работа Sherlock и Maigret с общим семафором процессов.
- Один редактируемый Telegram-прогресс с реальными состояниями и числом полученных результатов. Обновление раз в 3 секунды, с учётом Telegram RetryAfter.
- Отмена кнопкой или `/cancel`; уже полученные результаты и отчёты сохраняются.
- Контроль времени, памяти дерева процессов и количества соединений. Процессы завершаются и при отмене, и при исключениях.
- Объединение URL, группировка по хосту платформы, источники, UTC-время обнаружения, публичные метаданные и отметки возможных ложных совпадений.
- SQLite с таблицами `users`, `searches`, `profiles`, `reports`, `scan_logs`; все запросы к отчётам проверяют владельца.
- HTML с графитовой темой, адаптивной вёрсткой и экранированием, JSON, PDF с кириллицей и встроенным шрифтом.
- Отчёты хранятся BLOB-данными в SQLite, без общедоступного веб-сервера и файлов с результатами во временных каталогах.
- Автоудаление результатов и журналов проверки при запуске и раз в час; истёкшие отчёты недоступны сразу после истечения срока.
- Незавершённые задания после перезапуска отмечаются `interrupted`.
- Сетевые ошибки и ограничения сайтов не превращаются в утверждение «аккаунтов нет».

Настройки в Telegram показывают действующую конфигурацию. Изменения вносятся через `.env` и применяются после перезапуска.

## Как считаются результаты

**Проверено платформ** — количество разных хостов без `www.` с фактическим результатом проверки Sherlock/Maigret. Результаты `Illegal` исключаются: запрос для такого ника инструмент не делал. `Unknown` включается как неудавшаяся попытка, и причина отражается в отчёте. Несколько инструментов или определений одного хоста не увеличивают число платформ; отдельно сохраняется число результатов проверок инструментами.

**Найдено профилей** — уникальные безопасные HTTP(S) URL со статусом `Claimed`. Нормализация убирает фрагменты, известные tracking-параметры, завершающий `/`, различие `www` и схемы для ключа объединения. Регистр пути и параметры, идентифицирующие профиль, сохраняются. Это техническая нормализация, а не доказательство, что URL всегда эквивалентны.

**Подтверждённая доступная страница** — инструмент сообщил `Claimed` и HTTP 2xx именно для URL профиля. Успешный ответ отдельного API не подтверждает доступность страницы профиля. **Сомнительные совпадения** — остальные найденные URL. Ответы 401, 403, 429 и 5xx переводятся в `Unknown` и не становятся найденными аккаунтами.

**Уверенность** — качественная оценка совпадения: низкая для одного источника или неподтверждённой страницы; средняя для доступной страницы, совпавшей у нескольких инструментов. Проценты вероятности не выдумываются. Даже средняя уверенность не устанавливает личность; все профили сохраняют `possible_false_positive=true`.

Метаданные Maigret ограничены разрешёнными полями: публичное имя, ник, счётчики, дата создания и теги, когда библиотека действительно их извлекла. Пустые поля не дополняются предположениями. Email, телефоны, адреса, пароли, cookies, сырые HTML-страницы и дополнительные найденные идентификаторы не сохраняются. По извлечённым данным не запускаются новые проверки.

Базы платформ читаются из установленных пакетов, без сетевого обновления во время запуска. Поэтому программа запускает техническую проверку даже без интернета. Используются поддерживаемые установленной версией платформы после фильтрации источников, требующих обхода, авторизации или содержащих утечки.

## Конфигурация

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | пусто | Токен Telegram |
| `ADMIN_TELEGRAM_ID` | 0 | Единственный разрешённый Telegram ID |
| `DATA_DIR` | `data` в проекте | Каталог SQLite |
| `RETENTION_DAYS` | 7 | Хранение результатов, 1–365 дней |
| `SITE_LIMIT` | 500 | Максимум определений платформ на движок, 1–3000 |
| `CONNECTIONS` | 8 | Соединений на движок, 1–20 |
| `MAX_PROCESSES` | 2 | Одновременных процессов, 1–2 |
| `PROCESS_MEMORY_MB` | 768 | Лимит RSS дерева каждого процесса, 128–4096 МБ |
| `REQUEST_TIMEOUT` | 12 | Таймаут отдельного запроса, 1–60 с |
| `ENGINE_TIMEOUT` | 600 | Таймаут движка, 5–3600 с |
| `COOLDOWN_SECONDS` | 60 | Пауза между поисками, 10–3600 с |
| `SPIDERFOOT_CSV_EXPORT` | пусто | Необязательный путь к разрешённому CSV |
| `SPIDERFOOT_ALLOWED_USERNAMES` | пусто | Разрешённые ники CSV, через запятую, регистр учитывается |
| `SPIDERFOOT_PATH` | пусто | Путь к `sf.py` только для `--check` |
| `SPIDERFOOT_PYTHON` | пусто | Python отдельного окружения SF только для `--check` |

Для слабого ПК установите `MAX_PROCESSES=1`, `CONNECTIONS=4`, `SITE_LIMIT=100`. Ограничение памяти проверяется каждые 250 мс; это программный монитор, не жёсткий лимит Windows Job Object. При двух процессах суммарный лимит движков может достигать 1536 МБ плюс память бота и отчётов.

В Maigret 0.6.6 обнаружены автоматическая TLS-имперсонация на защищённых платформах и неверифицирующий SSLContext в обычном checker. Адаптер исключает `protection`, `activation`, зеркальные `source` и авторизованные определения, а внутри отдельного worker принудительно использует проверяемый TLS-контекст. Этот участок привязан к установленной версии и покрыт тестом. Обход Cloudflare, загрузка авторизационных cookies, Tor/I2P, обогащение дополнительными запросами, рекурсия и DNS-сканы отключены. Для поиска задано `retries=0`; встроенные транспортные повторы библиотеки при обрыве соединения и обычная обработка сессионных cookies остаются её поведением. Системные CA и сетевые настройки среды сохраняются.

## SpiderFoot: установлен отдельно, автоматический скан отключён

Проверена upstream-ревизия [`0f815a203afebf05c98b605dba5cf0475a0ee5fd`](https://github.com/smicallef/spiderfoot/tree/0f815a203afebf05c98b605dba5cf0475a0ee5fd), CLI сообщает SpiderFoot 4.0.0. В текущей среде отдельно установлены зависимости; реальные `sf.py --help` и `sf.py -M` завершились с кодом 0, `sfp_accounts` присутствует в списке.

Установка в общее окружение некорректна: Maigret требует `lxml>=6.0.2,<7`, SpiderFoot — `lxml>=4.9.2,<5`. Дополнительная установка, если нужна:

```powershell
.\.venv\Scripts\python.exe tools\install_spiderfoot.py
```

Скрипт использует Git и создаёт `.tools/spiderfoot` и `.tools/spiderfoot-venv`. Он не включает сетевые сканы. На Linux команда: `.venv/bin/python tools/install_spiderfoot.py`.

**Причина отключения автоматического запуска:** в проверенной версии `modules/sfp_accounts.py` вызывает запросы со случайным контрольным ником, а также `fetchUrl(... verify=False)`. Документированный CLI не предлагает флагов для отключения этих действий. Произвольные внутренние API и изменения исходников SpiderFoot для этого MVP не используются. Sherlock и Maigret продолжают работу, а в отчёте появляется понятное уведомление об отключённом модуле.

Независимый адаптер поддерживает **документированный CSV-вывод CLI** с заголовком `Source,Type,Data`. Он читает уже подготовленный и разрешённый экспорт, ничего не сканирует и не обращается к внутренней базе SpiderFoot:

1. Укажите путь к вашему экспорту в `SPIDERFOOT_CSV_EXPORT` и разрешённый ник в `SPIDERFOOT_ALLOWED_USERNAMES`.
2. CSV должен содержать событие `USERNAME` только для запрошенного ника; данные другого ника или нескольких целей отклоняются.
3. Импортируются только `ACCOUNT_EXTERNAL_OWNED` от `sfp_accounts`, только безопасные HTTP(S) ссылки из `<SFURL>…</SFURL>`. Домены, IP, email и другие типы событий игнорируются.
4. В отчёте стоит статус «импортирован CSV», низкая уверенность и время импорта, явно обозначенное в метаданных. Неизвестные отрицательные проверки SF не включаются в покрытие Sherlock/Maigret.
5. Максимум 16 МБ / 10000 строк. Исходный экспорт остаётся под вашим управлением и не удаляется механизмом хранения бота; при необходимости удалите его самостоятельно. Импортированная копия результата удаляется по обычному сроку.

Формат и параметры проверялись по upstream: [CLI](https://github.com/smicallef/spiderfoot/blob/0f815a203afebf05c98b605dba5cf0475a0ee5fd/sf.py), [модуль accounts](https://github.com/smicallef/spiderfoot/blob/0f815a203afebf05c98b605dba5cf0475a0ee5fd/modules/sfp_accounts.py). Наличие установленного CLI не означает, что сканирование разрешённых целей было проверено.

## Тестирование

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe main.py --check
```

Linux:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/python main.py --check
.venv/bin/python -m pip check
```

`--check` проверяет импорты, реальные локальные базы движков, SQLite, разделение владельцев и три формата отчётов в удаляемом временном каталоге. Токен для него не нужен. Он не запускает Telegram polling и сетевые проверки аккаунтов.

Автоматические тесты используют настоящие библиотеки и диспетчер aiogram с подменёнными HTTP/Telegram-ответами. Отдельные тесты действительно запускают и останавливают локальные дочерние процессы, не выполняющие сетевых запросов. Подробный результат проверки среды — в `TEST_RESULTS.md`.

Для проверки в Telegram после заполнения `.env` выполните `python main.py`, убедитесь в сообщении `Telegram authentication verified`, откройте `/start`, проверьте меню и запустите поиск **вашего разрешённого тестового ника**. Проверьте прогресс, `/cancel`, историю и загрузку трёх отчётов. Такие целевые проверки в текущем задании не выполнялись: токен и разрешённый тестовый аккаунт не предоставлены.

## Ограничения и известные проблемы

- Реальный Telegram polling и реальная проверка аккаунта требуют токена и разрешённой тестовой цели. Они не проверены в этой сессии. Токена в исходниках и `.env.example` нет.
- Выполнение и тесты проверены на Linux/Python 3.12.14. Windows 11 здесь недоступна; Windows-скрипт, пути и завершение процессов предусмотрены, но не проверены на настоящей Windows.
- Автоматический SpiderFoot отключён; поддерживается только описанный CSV-импорт.
- Реестры платформ меняются. Возможны ложные срабатывания, устаревшие правила, закрытые/переехавшие сайты, captcha, HTTP 429 и ограничения доступа. Бот отмечает такие результаты как неизвестные; прокси и дополнительные механизмы обхода не подключаются.
- Число доступных платформ может быть ниже `SITE_LIMIT`: учитываются фильтры, поддержка ника и локальная база конкретной версии. Никакое число профилей не гарантируется.
- Сохранение результатов происходит по завершении/отмене задания. При аварийном завершении ОС несохранённая часть теряется, задание получает `interrupted` при следующем запуске. Автоматического возобновления нет.
- Очередь в памяти; запуск нескольких экземпляров одного бота с одной БД не поддерживается. Горизонтальное масштабирование в MVP не реализовано.
- Отчёты хранятся в локальном SQLite без шифрования. За доступ к каталогу проекта и резервным копиям отвечает владелец ПК. Удаление в SQLite не удаляет уже отправленные Telegram-файлы или скачанные пользователем копии.
- Пока бот выключен, фоновая очистка не выполняется; она запускается при следующем старте. Настройки ретенции новых проверок не изменяют ранее установленный срок уже созданных запросов.
- Настройки меняются через `.env`, а не через Telegram. История показывает последние 10 проверок, профили — по 4 на странице.
- На очень больших выборках генерация PDF может занять время. При сбое обработки сохраняется JSON, а ошибка попадает в результат; остальные задания продолжают обрабатываться.
